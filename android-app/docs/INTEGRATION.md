# ShikshaEdge Backend & Teammate Integration Guide

## 1. Overview & Team Roles

- **Member 1 (This Repository / Android App)**:
  - Offline-first Flutter Android Client
  - SQLite offline database (`shikshaedge.db`)
  - Offline Bayesian Knowledge Tracing (BKT) Engine
  - Offline audio playback & structured asset packs
  - Persistent synchronization queue (`sync_queue` table)
- **Member 2 (Teammate / Web & Cloud)**:
  - Supabase Cloud Database & Auth
  - Teacher Web Dashboard (monitoring rural classrooms & student mastery)
  - ElevenLabs Educational Audio Generation
  - Cloud Content Distribution

> [!NOTE]
> This integration contract is **provisional** and designed to be non-blocking. The Android app functions with 100% features even if the backend is not yet deployed or credentials are blank.

---

## 2. Synchronization Architecture

```
[ Rural Smartphone (Offline) ]
             │
   (Student answers quiz)
             │
      ┌──────▼──────┐
      │  BKT Engine │ (Calculates updated mastery locally)
      └──────┬──────┘
             │
      ┌──────▼────────┐
      │ SQLite DB     │ (Atomically stores attempt & mastery)
      │  sync_queue   │ (Status: 'pending')
      └──────┬────────┘
             │
  (Internet becomes available)
             │
      ┌──────▼────────┐
      │  SyncService  │ (Checks Supabase URL & publishable key)
      └──────┬────────┘
             │
             ▼
[ Supabase Cloud Backend (PostgreSQL) ]
  ├── table: student_attempts
  ├── table: student_profiles
  └── table: classroom_mastery
             │
             ▼
[ Teacher Web Dashboard ] (Live classroom telemetry & analytics)
```

## 3. Data Models & Expected Backend Fields

### 3.1 Student Attempts (`student_attempts`)

Payload uploaded when synchronizing student quiz responses:

```json
{
  "id": "c1f7b702-861c-43bc-9d3c-9ad3bb1bc410",
  "student_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "question_id": "q_mult_06",
  "topic_id": "math_mult",
  "skill_id": "skill_mult_tables",
  "selected_option_id": "opt_06_b",
  "is_correct": true,
  "difficulty": "medium",
  "mastery_before": 0.40,
  "mastery_after": 0.69,
  "answered_at": "2026-11-24T06:30:00.000Z",
  "created_at": "2026-11-24T06:30:00.000Z"
}
```

| Field Name | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique attempt UUID generated on Android client (idempotent) |
| `student_id` | UUID (FK) | Unique student identifier |
| `question_id` | TEXT | Identifier of question from content pack |
| `topic_id` | TEXT | Topic identifier (e.g. `math_mult`, `sci_photo`) |
| `skill_id` | TEXT | Skill identifier within the topic |
| `selected_option_id` | TEXT | Selected answer option ID |
| `is_correct` | BOOLEAN | Correctness flag (true/false) |
| `difficulty` | TEXT | Question difficulty (`easy`, `medium`, `hard`) |
| `mastery_before` | NUMERIC | Bayesian probability before answering ($0.0 - 1.0$) |
| `mastery_after` | NUMERIC | Updated Bayesian probability after response ($0.0 - 1.0$) |
| `answered_at` | TIMESTAMPTZ | ISO timestamp when student submitted answer |
| `created_at` | TIMESTAMPTZ | Record creation timestamp |

## 4. Authentication & Security Policy

1. **Client-Side Secrets**:
   - The Android app ONLY accepts the `SUPABASE_URL` and `SUPABASE_ANON_KEY` (public/anon key).
   - **NEVER** expose or commit the `SUPABASE_SERVICE_ROLE_KEY` to the Android application.
2. **Child Privacy & Safety**:
   - No phone numbers, emails, passwords, biometric data, or location tracking are collected.
   - Profile uses display name and avatar on shared rural devices.
   - Row-Level Security (RLS) policies on Supabase should restrict modifications.

## 5. Audio Asset Naming Convention (ElevenLabs)

Educational voice files generated by the backend team must follow this layout:

```
assets/audio/{language_code}/{subject}/
  ├── assets/audio/en/mathematics/math_mult_intro.mp3
  ├── assets/audio/kn/mathematics/math_mult_intro.mp3
  ├── assets/audio/en/science/sci_photo_intro.mp3
  ├── assets/audio/kn/science/sci_photo_intro.mp3
  ├── assets/audio/en/english/eng_nouns_intro.mp3
  └── assets/audio/kn/english/eng_nouns_intro.mp3
```

- **Audio format**: MP3 (Mono or Joint Stereo, 64-128 kbps, 44.1 kHz, optimized for low storage).
- **Naming Rule**:
  - Lessons: `{topic_id}_intro.mp3` or `{lesson_id}.mp3`
  - Questions: `{topic_id}_q{number}.mp3` (e.g. `math_mult_q1.mp3`)

## 6. Offline Content-Pack Schema

Content packs are distributed as lightweight JSON assets (`assets/content/{pack_name}.json`):

```json
{
  "pack_id": "pack_class_6_v1",
  "version": "1.0.0",
  "name": "Class 6 Foundation Learning Pack",
  "class_id": "class_6",
  "subjects": [
    {
      "id": "math_6",
      "class_id": "class_6",
      "name": "Mathematics",
      "name_kn": "ಗಣಿತ",
      "topics": [ ... ]
    }
  ]
}
```
All content packs can be imported into SQLite safely using atomic transactions and duplicate prevention logic (`DatabaseHelper.seedInitialContentPack()`).
